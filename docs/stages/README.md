# 단계별 재구성 기록 (rebuild 브랜치)

0.6.2 까지의 파이프라인(분류기 1차 → LLM 2차, 전처리·후처리 일체)은 결과는 냈지만 **어느 요소가 결과를 얼마나 바꿨는지** 분리해 보여 주지 못했다.
1.0 계열은 판정 파이프라인을 비운 뒤 한 요소씩 다시 붙이며, 붙일 때마다 "전과 후에 결과물이 어떻게 달라졌는가"를 사람이 읽을 수 있는 표로 남긴다.
이 폴더의 문서가 그 기록이다. 숫자는 회사 PC 의 실제 보고서·골드로 측정해 채운다(저장소에는 실제 문장을 넣지 않는다).

| 단계 | 문서 | 내용 | 측정 명령 |
|---|---|---|---|
| 0 | [00-baseline.md](00-baseline.md) | 기준선: 읽기(원시) → 1차 분류기 → 점수 → Excel. 스위치 전부 끔 | `run-all`, `compare-runs` |
| 1 | [01-classifier.md](01-classifier.md) | 1차 분류기 후보 7종을 골드 교차 검증으로 비교해 하나 고르기 | `compare-classifiers`, `ladder --ladder ladders/classifiers.toml` |
| 2 | [02-preprocessing.md](02-preprocessing.md) | 레이아웃 분석과 전처리·후처리 스위치를 한 칸씩 켜며 기여 측정 | `ladder --ladder ladders/switches.toml` |
| 3 | [03-llm.md](03-llm.md) | LLM 2차 판정 부착 (아직 코드 없음) | 같은 사다리 틀 |

## 모든 단계가 같은 지표를 쓴다

| 지표 | 뜻 | 어디서 보나 |
|---|---|---|
| A·B 재현율 | 골드에서 정답이 A·B 인 문장 중 검토 목록에 오른 비율 (놓침) | 사다리 요약, 비교 '골드 지표', 분류기 비교 요약 |
| A·B 정밀도 | 검토 목록 중 정답이 A·B 인 비율 (검토 부담) | 같음 |
| 등급 정확도 · 거시 F1 | 5등급을 그대로 맞춘 정도 | 분류기 비교 요약·등급별·혼동 행렬 |
| 검토 목록 수 (/ 보고서) | 사람이 읽어야 하는 양 | 사다리 요약, 비교 요약 |
| 처리 시간 / 보고서 | 속도 | 같음 |

문장 맞추기 규칙(비교·채점 공통): 동일(공백 무시) → 포함(한쪽이 다른 쪽 안에: 합쳐짐·나뉨) → 유사(글자 일치 0.6 이상). `ip_finder/compare/matching.py`.

## 결과를 보고서에 옮기는 법

각 명령은 Excel 과 같은 숫자의 Markdown(`.md`)을 함께 만든다. Markdown 의 표는 숫자만 있으므로 그대로 보고서에 붙여도 실제 문장이 새지 않는다.
문장 단위 근거(어떤 문장이 들어오고 나갔는가)는 Excel 의 '변경 문장'·'칸별 변화' 시트에 있다.

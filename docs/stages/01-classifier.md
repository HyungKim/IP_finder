# 1단계 — 1차 분류기 고르기

**질문**: 임베딩 + 어떤 판정 규칙이 우리 골드에서 가장 잘 맞고, 임베딩(또는 학습)이 정말 필요한가?

## 후보

| 이름 | 학습 | 임베딩 | 한 줄 설명 | 왜 넣었나 |
|---|---|---|---|---|
| cue | X | X | 단서어 정규식 규칙 | 기계학습 없는 바닥선 |
| ngram | O | X | 글자 2·3-gram 해시 + 소프트맥스 | 임베딩 모델 없이 되는지 |
| proto | X | O | 등급별 원형 문장과 코사인 (제로샷) | 골드가 없을 때의 출발점 (0.x 기본) |
| knn | O | O | 가장 가까운 골드 문장 k 개 다수결 | 골드가 늘면 바로 반영, 설명이 쉬움 |
| centroid | O | O | 등급별 평균 벡터와 코사인 | 가장 단순한 학습형 |
| softmax | O | O | 소프트맥스 회귀 (임베딩 + 단서 13개) | 0.x 의 학습 분류기 |
| ovr | O | O | 일대다 로지스틱 | 어느 등급에도 확신 없는 문장을 드러냄 |

임베딩 모델(bge-m3, kure-v1)은 `--embed-model` 로 바꿔 한 번 더 돌리면 비교 축이 된다. Laya 같은 결정 모델은 PyTorch 가 필요해 후보에서 뺐다.

## 측정 방법 (회사 PC)

1. 골드가 있어야 한다. 없으면 `ui.bat` 정확도 관리 탭에서 골드 시트를 만들어 정답을 채운다(최소 20문장, 권장 100 이상).
2. 학습형 파일 만들기 (각각): `ip-finder train --classifier knn` 등. 비교 명령은 교차 검증으로 스스로 학습하므로 이 단계는 실제 보고서에 적용할 때만 필요하다.
3. 교차 검증 비교:
   ```bat
   compare_classifiers.bat --out results\classifiers.xlsx
   ```
   요약 시트의 '정확도 표준편차'보다 작은 차이는 잡음으로 본다.
4. 실제 보고서 위에서 후보 수·시간 비교(선택): `ladder.bat results\ladder_classifiers D:\reports --ladder ladders\classifiers.toml`

## 해석 지침

- 정밀도 우선 과제이므로 A·B 정밀도가 높은 쪽을 먼저 보고, 재현율이 크게 떨어지지 않는지 확인한다.
- cue 와 ngram 이 임베딩 분류기에 크게 뒤지면 "임베딩이 필요하다"는 근거가 된다. 비슷하면 임베딩 모델 없이도 되는 것이다.
- 골드가 적으면(100 미만) 표준편차가 크다. 결론을 내기 전에 골드를 늘리는 것이 가장 싼 개선이다.

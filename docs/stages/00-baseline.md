# 0단계 — 기준선: 1차 분류기만

**가설**: 아무 규칙도 없이 분류기만 돌린 결과가 출발점이다. 이후 모든 개량은 이 결과와의 차이로 측정한다.

## 바꾼 것 (코드)

- LLM 2차 판정과 프롬프트(`label/`, `llm/`)를 뺐다. 판정은 1차 분류기 하나다.
- 읽기(`layout_analysis`), 줄 규칙 5개, 페이지 규칙 3개, 후처리 2개가 모두 **스위치**(`ip_finder/switches.py`)가 됐고 기본값은 전부 끔이다.
  `ip-finder switches` 가 목록을, Excel '실행 정보' 시트가 실행에 쓰인 상태를 보여 준다.
- 원시 읽기(레이아웃 분석 끔): PDF 는 PyMuPDF 기본 추출 줄 그대로, PPTX 는 도형 순서대로 문단 그대로. 첫 줄(또는 제목 자리)이 제목.
- 1차 분류기 7종이 같은 인터페이스(`classify/base.py`)로 묶였고 설정 `classifier` 로 고른다.
- 결과 Excel 에 '전처리 제외' 시트(규칙에 걸린 줄과 사유)와 '설정 ' 행이 생겨 결과 파일만으로 전후를 비교할 수 있다.
- 비교 명령 세 개: `run-all`(한 설정으로 전부 실행), `compare-runs`(결과 둘 비교), `ladder`(스위치 사다리). 분류기 비교는 `compare-classifiers`.

## 측정 방법 (회사 PC)

```bat
run_all.bat results\s0-baseline D:\reports
```
기준선 결과 폴더가 생긴다. 이 폴더는 이후 모든 비교의 A(이전) 가 된다.

## 결과 (채워 넣기)

| 항목 | 값 |
|---|---|
| 보고서 수 / 총 페이지 | |
| 문장 단위 수 (전체) | |
| 검토 목록 수 (A / B) | |
| A·B 재현율 / 정밀도 (골드 기준) | |
| 처리 시간 (초 / 보고서) | |

## 읽을 때 주의

기준선은 제목·꼬리말·표 셀·쪽 번호까지 전부 판정하므로 검토 목록이 매우 길고 잡음이 많다. 이것은 결함이 아니라 출발점이며, 2단계의 각 스위치가 이 잡음을 얼마나 줄이는지가 보고서의 숫자가 된다.

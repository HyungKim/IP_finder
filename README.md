# IP Finder

보고자료(PDF / PPTX)를 읽어 **특허팀과 논의할 만한 기술 문장을 뽑고, 단서 등급(A/B/C/D)과 점수를 붙인 Excel 목록**을 만드는 도구입니다.
판정은 PC 안의 로컬 임베딩 분류기와 로컬 LLM(Ollama)이 하고, 외부로는 아무것도 보내지 않습니다. GPU 없는 윈도우 PC(RAM 16GB)에서 돌아가도록 설계했습니다.
기본 판정 모드는 **cascade**입니다. 임베딩 분류기가 모든 문장을 **1차**로 판정해 **A(수단)·B(효과)** 로 본 문장만 후보로 뽑고, 그 후보 전부를 LLM이 **2차**로 판정해 A인지 B인지 최종 등급을 매깁니다. LLM이 C·D·X로 보면 제외됩니다. 검토 목록에는 두 단계를 모두 통과한 A·B 문장만 오르고, 1차에서 걸러진 문장은 LLM 비용이 들지 않습니다. 과제(C)·계획(D)까지 뽑으려면 추출 등급을 "A·B·C·D"로 바꿉니다.

**정밀도 우선**입니다. 몇 개를 놓치더라도 확실한 것만 검토 목록에 올립니다.
- 페이지 **제목**(위쪽의 큰 글씨)으로 관련성을 **높음/낮음** 둘 중 하나로 정합니다. 현황·실적·고객·클레임·영업·회의 같은 제목은 낮음(가중치 0.4), 나머지는 높음(1.0). 문장 점수 = 판정 신뢰도 × 페이지 가중치이고, 점수가 기준(기본 0.5) 미만이면 검토 목록 대신 **보류** 시트로 갑니다. UI 체크박스로 끌 수 있습니다.
- 결과 Excel의 문장 시트마다 **1차 분류기 / 2차 LLM** 열이 있고, 1차에서 뽑혔다가 2차에서 빠진 문장은 **'2차 제외' 시트**에 따로 모입니다. 잘못 빠진 것은 그 시트의 피드백 열에 등급을 적어 살립니다.
- 결과 Excel의 **피드백** 열에 O / X / A~D 만 적으면 골드 시트가 되고, 그것으로 분류기를 학습합니다. 골드에 있는 문장은 다음 실행부터 모델 판정 대신 **골드 정답을 그대로** 씁니다. 사람이 확정한 판정은 업그레이드나 재실행으로 뒤집히지 않습니다.
- 실행마다 이력이 남아, 같은 보고서를 다시 돌리면 **직전 실행과 달라진 행**(목록 진입·이탈, 등급 변경)과 **달라진 설정**이 Excel '변경 사항' 시트와 UI '변경 추적' 탭에 나옵니다.

- 원본 파일은 읽기만 하고 수정하지 않습니다. 결과는 원본 옆에 `<이름>_검토후보.xlsx` 로 생깁니다.
- 이 단계에서 신규성·진보성은 판단하지 않습니다. 구체적 수단이 없어도 효과, 과제, 변경 의도가 있으면 후보가 됩니다. 최종 판단은 사람이 합니다.
- 설계 배경과 결정 사항은 [PROPOSAL.md](PROPOSAL.md), 입력과 출력 예시는 [EXAMPLE.md](EXAMPLE.md), 모델 실험 기록은 [demo/](demo/README.md)에 있습니다.

## 단서 등급

기본 추출 등급은 **A·B**입니다 (설정 `target_grades`, UI '추출 등급'). C·D는 기본으로는 1차에서 걸러져 '1차 제외 (참고)' 시트에만 남습니다.

| 등급 | 의미 | 특허팀 논의 포인트 (자동 기입) |
|---|---|---|
| A 수단 명시 | 구조, 재료, 공정 조건, 알고리즘, 파라미터 등이 문장 안에 직접 적힘 | 기존 방식과 무엇이 다른가. 변형 가능한 범위는. |
| B 효과 기재 | 개선, 저감, 수치 비교, 기존 대비. 수단은 없음 | 이 효과를 얻은 구체적 수단은 무엇인가. |
| C 과제 제기 | 현상, 불량 원인, 메커니즘, 기존 방식의 한계 | 이 문제의 해결 수단이 있는가, 시도 중인가. |
| D 변경 시사 | 적용 예정, 검토 중, 도입 계획 | 변경 내용의 구체적 구성은 무엇인가. |
| X 제외 | 일정, 비용, 인력, 고객 대응, 표준 개정, 단순 현황, 구체성 없는 일반 설명 | 리포트에 싣지 않음. 기술 단서어가 있으면 `X?`로 보류 시트에 |

등급과 별도로 문장마다 **점수**(0~1)가 붙습니다. 점수 = 판정 신뢰도 × 페이지 가중치. A~D 라도 점수가 기준(기본 0.5) 미만이면 보류 시트로 갑니다 (사유 기재).
기준 전문은 [ip_finder/label/prompts/rubric.md](ip_finder/label/prompts/rubric.md), LLM에 들어가는 압축판은 [system.md](ip_finder/label/prompts/system.md)입니다. 회사 보고서에 맞게 고쳐 쓰면 됩니다. 프롬프트는 "확신이 없으면 X"로 정밀도 우선입니다.

## 다운로드

- 저장소: https://github.com/HyungKim/IP_finder
- 소스 ZIP: https://github.com/HyungKim/IP_finder/archive/refs/heads/main.zip (저장소 페이지의 **Code → Download ZIP** 과 같음)
- 릴리스: https://github.com/HyungKim/IP_finder/releases/latest — 소스 ZIP과 **윈도우 오프라인 설치용 wheel 번들** `ip_finder_wheels_win_amd64_py312.zip`(Python 3.12 64비트용, 38MB). 다른 Python 버전용 번들은 `tools\download_wheels.bat`로 만듭니다.

저장소는 공개이므로 로그인 없이 받을 수 있습니다. 실제 보고서, 골드 세트, 결과 파일은 절대 이 저장소에 올리지 마세요.

## 윈도우 간편 설치 (install.bat)

1. Python 3.12 64비트를 설치합니다 (https://www.python.org/downloads/windows/ , "Add python.exe to PATH" 체크).
2. Ollama를 설치합니다 (https://ollama.com/download/windows).
3. 소스 ZIP을 원하는 폴더에 풀고 `install.bat`를 더블클릭합니다. 가상환경 생성, 패키지 설치, 모델 내려받기(`qwen3:4b-instruct`, 약 2.5GB), 환경 확인까지 자동으로 진행됩니다.
   캐시, 학습한 분류기, 실행 이력, 설정 파일은 모두 **그 폴더의 `data\` 와 `ip_finder.toml`** 에만 생깁니다. 사용자 홈 폴더에는 아무것도 만들지 않으므로, 폴더를 여러 개 두면 설치본마다 완전히 따로 관리됩니다 (Ollama 모델만 PC 전체에서 공유).
4. `ui.bat`를 더블클릭해 창에서 쓰거나, `extract.bat` 위로 보고서 파일이나 폴더를 끌어다 놓으면 원본 옆에 `이름_검토후보.xlsx`가 생깁니다. 명령줄에서는 `extract.bat 보고서.pptx`.

인터넷이 막힌 PC라면:
- 패키지: 릴리스의 wheel 번들을 받아 압축을 풀고, 생긴 `wheels` 폴더를 `install.bat` 옆에 둔 뒤 실행합니다. `wheels` 폴더가 있으면 PyPI에 접속하지 않습니다. 다른 Python 버전이면 인터넷이 되는 윈도우 PC에서 `tools\download_wheels.bat 3.13` 처럼 실행해 번들을 직접 만듭니다.
- 모델: 다른 PC에서 `ollama pull qwen3:4b-instruct` 후 `%USERPROFILE%\.ollama\models` 폴더를 복사합니다.

배치 파일은 Python을 찾아 가상환경을 만드는 일만 하고, 패키지 설치, Ollama와 모델 확인, 환경 점검은 `tools/setup_windows.py`가 합니다. 그래서 Python을 찾기 전까지의 메시지는 영어이고 그 뒤부터 한글입니다. 패키지를 설치하지 않고 저장소 폴더에서 `python -m ip_finder.cli`로 실행하므로 아래의 `pip install -e .` 없이도 동작합니다.

문제 해결
- `'...'은(는) 내부 또는 외부 명령, 실행할 수 있는 프로그램, 또는 배치 파일이 아닙니다.` — v0.1.0의 배치 파일에 한글이 들어 있어 생기던 문제입니다. 한글 Windows의 cmd.exe는 UTF-8 모드에서 다중 바이트 문자가 있는 줄의 위치를 잘못 계산해 줄의 나머지를 명령으로 실행합니다. v0.1.1부터 배치 파일은 ASCII만 쓰므로 최신 ZIP을 다시 받으세요.
- 콘솔에서 한글이 네모로 보이면 창 속성에서 글꼴을 '맑은 고딕'이나 'Consolas'로 바꾸세요.
- `py` 런처도 `python`도 없다고 나오면 Python 설치 시 "Add python.exe to PATH"를 체크하지 않은 것입니다. 재설치하거나 PATH에 추가하세요.

## 업데이트 방법

`install.bat`는 몇 번을 다시 실행해도 안전합니다. 이미 있는 가상환경, 패키지, 모델은 건너뛰고 빠진 것만 채웁니다.

1. 최신 릴리스의 소스 ZIP을 받아 **기존 폴더 위에 덮어씁니다** (`.venv` 폴더가 남아 재설치가 필요 없음). git으로 받았다면 `git pull`.
2. 새 버전에 패키지나 모델이 추가됐으면 `install.bat`를 다시 실행합니다. 인터넷이 막힌 PC는 릴리스의 새 wheel 번들을 `wheels` 폴더로 두고 실행하고, 새 Ollama 모델은 다른 PC에서 `ollama pull` 후 `%USERPROFILE%\.ollama\models` 폴더를 복사합니다.
3. 새 폴더에 풀었다면 `install.bat`를 실행합니다. 가상환경을 다시 만들어 패키지를 설치하지만, Ollama 모델은 PC에 이미 있어 건너뜁니다.

| 올라오는 버전 | 필요한 일 |
|---|---|
| v0.1.x → 현재 | `install.bat` 재실행. numpy 패키지와 임베딩 모델 `bge-m3`(약 1.2GB)가 추가됩니다 |
| v0.2.0 / v0.3.0 → 현재 | 파일만 바꾸면 됩니다. 새 패키지·모델 없음. KURE-v1 을 쓰려면 아래 '모델 선택' 참고 |
| v0.4.x / v0.5.0 → 현재 (v0.5.1) | 파일만 바꾸면 됩니다. `data\`(골드·분류기·캐시·이력)와 `ip_finder.toml` 은 그대로 이어지고, 옛 설정의 `mode = "hybrid"` 와 `page_weights` 는 자동으로 cascade 와 낮음 키워드로 읽힙니다. 프롬프트가 같아 LLM 캐시도 유지 |

**이전 버전이 설치된 PC 에서 새 릴리스를 설치하는 순서**
1. 릴리스 페이지에서 **Source code (zip)** 을 받습니다.
2. ZIP 을 풀면 `IP_finder-<버전>` 폴더가 한 겹 생깁니다. 그 **안의 내용물**을 기존 설치 폴더(`ui.bat` 가 있는 곳) 위에 복사해 덮어씁니다. `.venv\`, `data\`, `ip_finder.toml` 은 ZIP 에 없으므로 그대로 남습니다.
3. 새 패키지나 모델이 추가된 버전이면(릴리스 노트에 적힘) `install.bat` 를 한 번 더 실행합니다. 그렇지 않으면 바로 `ui.bat`.
4. `ui.bat` 의 환경 점검 줄이나 `ip-finder check` 로 버전과 설치 폴더를 확인합니다.
5. 같은 보고서를 다시 돌리면 '변경 사항' 시트의 달라진 설정에 "프로그램 버전 …" 이 찍히고, 버전 때문에 달라진 행을 볼 수 있습니다.

새 폴더에 따로 설치하려면 ZIP 을 새 폴더에 풀고 `install.bat` 를 실행한 뒤, 이전 폴더의 `data\` 와 `ip_finder.toml` 을 복사하면 골드·분류기·이력이 이어집니다.

따로 손댈 것은 없습니다. 캐시는 프롬프트 버전이 바뀌면 이전 판정 결과를 자동으로 무시하고, 이전에 만든 골드 시트는 열 구성이 달라져도 그대로 읽힙니다.
v0.4.0은 프롬프트가 바뀌어(정밀도 우선) 첫 실행에서 LLM 캐시를 다시 채웁니다. 결과 Excel의 시트와 열 구성이 바뀌었으니 이전 결과 파일에 적은 피드백은 새 결과 파일에 다시 적으세요.

**새 폴더에 따로 설치하기**: 기존 폴더를 두고 새 폴더에 ZIP을 풀어 `install.bat`를 실행하면 됩니다. v0.4.1부터 캐시·분류기·이력이 설치 폴더의 `data\` 아래에 생기므로 두 설치본은 서로 아무것도 공유하지 않습니다 (Ollama 모델만 공유). v0.3 이하에서 `%USERPROFILE%\.ip_finder\classifier.npz` 로 학습해 둔 분류기를 이어 쓰려면 그 파일을 새 폴더의 `data\classifier.npz` 로 복사하세요. 캐시는 프롬프트가 바뀌어 어차피 다시 채워지니 옮기지 않아도 됩니다.

## 데스크톱 UI

명령줄이 익숙하지 않으면 창을 띄워 쓰면 됩니다. 추가 설치는 없습니다 (Python에 포함된 Tkinter).

- 윈도우: `ui.bat` 더블클릭. 다른 환경: `ip-finder ui` 또는 `python -m ip_finder.ui`
- **추출 탭**: 파일·폴더 추가 → 판정 모드, 모델, 목록 점수 기준, **페이지 가중치 적용** 체크박스, 결과 위치 → 실행. 진행 로그가 흐르고 끝나면 미리보기 표(등급별 색, 점수, 가중치, 1차·2차 라벨, 판정 주체)가 채워집니다. '보기'에서 검토 목록, 등급별, 보류, **2차 제외(1차 통과분)**, 1차 제외(참고)를 고릅니다. "결과 Excel 열기"로 바로 엽니다. **중지 버튼은 진행 중인 Ollama 호출을 즉시 끊습니다.** 끝난 문장은 캐시에 남아 다음 실행에서 재사용됩니다.
- **페이지 가중치 탭**: 마지막 실행의 페이지마다 제목, 관련성(높음/낮음), 가중치, 근거, 목록·보류·1차 제외·2차 제외 수가 표로 나옵니다(낮음은 회색). 오른쪽에서 가중치 적용 스위치, 낮음 가중치, 낮음 키워드(정규식, 한 줄에 하나), 높음으로 강제할 키워드를 고쳐 "규칙 적용"(이번 세션) 또는 "설정 저장..."(설치 폴더의 `ip_finder.toml`, 이후 UI와 명령줄이 함께 읽음)을 누릅니다. "보고서 골라 미리 보기"는 LLM 없이 제목·관련성만 계산해 키워드를 빠르게 점검합니다.
- **정확도 관리 탭**: ① 골드 시트 만들기 → ② 결과 Excel의 피드백 가져오기(골드 시트에 합침) → ③ 분류기 학습 → ④ 채점(등급 정확도 + 검토 목록 정밀도, 점수 기준별 표). 모두 버튼 하나씩이며 출력은 아래 창에 나옵니다.
- **변경 추적 탭**: 실행 이력 표(시각, 파일, 모드·모델·분류기, 목록 수, 보류, 직전 대비 진입·이탈·등급 변경, 달라진 설정). 행을 고르면 상세가, 아래에는 마지막 실행에서 달라진 문장과 피드백·학습 이력이 나옵니다.
- 아래 상태 줄에 Ollama 연결, LLM·임베딩 모델 설치 여부, 현재 분류기(제로샷/학습됨)가 표시됩니다.

## 판정 모드

| 모드 | 동작 | 언제 |
|---|---|---|
| **cascade** (기본) | **1차**: 임베딩 분류기가 모든 문장을 판정해 추출 등급(기본 A·B)으로 본 문장만 후보로. **2차**: 후보 전부를 페이지 유형별로 묶어 LLM이 판정해 최종 등급(A/B). 2차에서 C·D·X면 '2차 제외'. 1차와 2차 등급이 다르면 비고에 '불일치' | 평소 |
| fast | 분류기만 (추출 등급만 목록). 수십 초 안에 끝남 | 훑어보기, 수백 건 일괄 처리, 임베딩 속도 점검 |
| llm | 모든 페이지를 LLM이 판정 (분류기 없음, 추출 등급만 목록) | 분류기를 못 믿을 때, 임베딩 모델이 없을 때 |

- 분류기는 두 가지입니다. 골드 세트로 학습한 파일(설치 폴더의 `data\classifier.npz`)이 있으면 그것을, 없으면 등급별 원형 문장([prototypes.json](ip_finder/classify/prototypes.json))과의 유사도로 판정하는 제로샷 분류기를 씁니다.
- 결과 Excel의 문장 시트에는 **'1차 분류기'와 '2차 LLM' 열**이 있어 어느 단계가 무엇으로 판정했는지 바로 보입니다. '판정' 열은 최종 판정 주체(분류기/LLM/골드).
- **'2차 제외' 시트**: 1차에서 A·B로 뽑혔다가 2차 LLM이 C·D·X로 본 문장. 잘못 제외된 것이 있는지 여기서 확인하고, 피드백 열에 A나 B를 적어 골드로 살립니다. 분류기가 1차에서 C·D·X로 본 문장은 맨 뒤 '1차 제외 (참고)' 시트에 있습니다.
- **추출 등급**(`target_grades`, 기본 `"A,B"`, UI 추출 탭의 '추출 등급', 명령줄 `--grades`): 1차 후보와 2차 판정의 기준이 되는 등급. `"A,B,C,D"`로 넓히면 과제·계획 문장도 목록에 오르지만 2차 후보가 늘어 LLM 시간이 늘어납니다.
- LLM에는 페이지 제목에서 계산한 "페이지 유형" 힌트 한 줄이 함께 들어갑니다. 원인 분석 페이지의 설명 문장을 수단으로 올리는 오류가 이 힌트로 크게 줄었습니다.
- 이전 버전의 hybrid 모드(애매한 문장만 LLM), LLM 재확인 옵션, 확신 임계값은 v0.5.0에서 없어졌습니다. 옛 설정의 `mode = "hybrid"`는 cascade로 읽힙니다.

## 페이지 가중치와 점수 (정밀도 우선)

"관련 없는 문장이 너무 많이 올라온다"는 문제를 페이지 단위로 누릅니다. 제목은 문서 위쪽에 큰 글씨로 있으므로 PDF는 글꼴 크기로, PPTX는 제목 플레이스홀더(없으면 위쪽에서 글꼴이 가장 큰 상자)로 찾습니다. 결과 Excel '페이지' 시트의 '제목 출처' 열에서 어떻게 찾았는지 확인할 수 있습니다.

| 단계 | 내용 |
|---|---|
| 관련성 (두 분류) | 제목이 **낮음 키워드**(`low_relevance_patterns`, 정규식)에 걸리면 **낮음**(가중치 `low_relevance_weight`, 기본 0.4), 아니면 **높음**(1.0). **높음 키워드**(`high_relevance_patterns`)는 낮음보다 우선. 낮음 가중치를 0으로 두면 낮음 페이지는 판정하지 않음. `page_weight_enabled = false`(UI 체크박스, `--no-page-weight`)면 모두 1.0 |
| 판정 신뢰도 (0~1) | 1차·2차 등급 일치 1.0 / 2차 등급이 1차와 다름(불일치) 0.65 / LLM만(llm 모드) 0.9 / 분류기만(fast): 학습 분류기 = 1위 확률, 제로샷 = 0.65 + 유사도 차이(최대 0.9) / 골드 반영 1.0 / 판정 실패 0 |
| 점수 | 신뢰도 × 가중치. `accept_score`(기본 0.5) 이상이면 검토 목록, 미만이면 보류 시트에 사유("점수 0.40 < 0.50 (가중치 0.40)")와 함께 |

기본 낮음 키워드는 고객·클레임·영업·매출·수주·회의·교육·인사·채용·복지, 현황·실적·진행 상황·동향·경과 입니다. 회사 템플릿의 제목어는 UI '페이지 가중치' 탭이나 `ip_finder.toml`에 추가합니다. `ip-finder pages 보고서.pptx` 는 LLM 없이 페이지별 제목·관련성·가중치·제외 여부만 보여 줍니다.

점수 기준을 올리면 목록이 짧고 확실해지며, 걸러진 문장은 보류 시트에 그대로 남으므로 잃어버리지는 않습니다. 골드 시트로 `eval` 하면 점수 기준별 목록 정밀도·재현율 표가 나와 기준을 숫자로 고를 수 있습니다.

## 요구 사항

- Windows 10/11 또는 macOS. Python 3.11 이상 (3.12 권장).
- [Ollama](https://ollama.com) 와 모델 두 개: LLM `qwen3:4b-instruct` (약 2.5GB), 임베딩 `bge-m3` (약 1.2GB). 임베딩 모델이 없으면 llm 모드로 동작합니다.
- 선택: 정확도 우선이면 LLM `qwen3:8b` (약 5.2GB, thinking 은 자동으로 끔). 한국어 임베딩 `KURE-v1` 은 아래 절차로 들여옵니다.
- 선택: 구형 `.ppt` 입력은 PowerPoint가 설치된 윈도우에서 `pywin32`로 자동 변환합니다.

### 모델 선택 (Qwen3 8B, KURE-v1)

| 역할 | 기본 | 대안 | 판단 |
|---|---|---|---|
| LLM | `qwen3:4b-instruct` (Qwen3-4B-Instruct-2507 Q4_K_M) | `qwen3:8b` (Q4_K_M, 약 5.2GB, 실행 시 6~7GB) | 같은 샘플에서 라벨 정확도 4B 21/26, 8B 25/26. 시간은 2배. cascade 에서는 분류기가 거른 문장을 LLM 이 보지 않으므로 8B 의 시간 부담이 작아 **정밀도 우선이면 8B 권장**. Ollama 의 `qwen3:8b` 는 thinking 겸용 모델이며 이 도구는 모든 호출에 `think=false` 를 붙입니다 (별도 instruct 태그 없음) |
| 임베딩 | `bge-m3` (Ollama 공식, 1.2GB) | `kure-v1` (bge-m3 를 한국어로 미세조정, MIT) | KURE 측 벤치마크(MTEB-ko 검색)에서 nDCG@10 0.7616 vs 0.7509 로 1점 남짓 우위. 분류용 차이는 회사 골드 세트로 재야 합니다. 분류기는 임베딩 모델에 묶이므로 교체 후 `train` 을 다시 합니다 |

**KURE-v1 들여오기** (Ollama 라이브러리에 없어 GGUF 를 직접 넣습니다. 추가 Python 패키지 없음)
1. https://huggingface.co/Bingsu/KURE-v1-Q8_0-GGUF 에서 `kure-v1-q8_0.gguf` (약 635MB, Q8_0 양자화) 를 받아 `tools\kure\` 폴더에 둡니다. 인터넷이 막힌 PC 는 다른 PC 에서 받아 복사합니다.
2. `tools\import_kure.bat` 를 실행합니다 (`ollama create kure-v1 -f tools/kure/Modelfile`).
3. UI 의 임베딩 모델 상자에서 `kure-v1` 을 고르거나, `--embed-model kure-v1`, 또는 설정 파일 `embed_model = "kure-v1"`. 골드 세트가 있으면 `eval --mode fast --embed-model kure-v1` 과 `bge-m3` 를 비교해 고릅니다.

## 사용

```bash
ip-finder extract 보고서.pptx                 # 결과: 보고서_검토후보.xlsx (원본 옆)
ip-finder extract 보고서.pdf 다른보고서.pptx    # 여러 파일
ip-finder extract 보고서폴더/ --out-dir 결과/   # 폴더 전체(하위 폴더 포함), 결과를 한곳에
ip-finder extract 보고서.pptx --model qwen3:8b  # LLM 교체 (think 계열도 자동으로 think=false)
ip-finder extract 보고서.pptx --mode fast       # 분류기만 / --mode llm 전부 LLM
ip-finder extract 보고서.pptx --accept-score 0.7 --no-page-weight   # 목록 기준 상향 / 페이지 가중치 끔
ip-finder extract 보고서.pptx --grades A,B,C,D   # 과제·계획까지 추출 (기본 A,B)
ip-finder pages 보고서.pptx                     # LLM 없이 페이지별 제목·관련성·가중치·제외 여부 확인
ip-finder feedback 보고서_검토후보.xlsx           # 결과 Excel의 '피드백' 열 → 보고서_gold.xlsx (있으면 합침)
ip-finder history                               # 실행·피드백·학습 이력, 직전 실행 대비 변경 요약
```

진행률이 페이지마다 찍히고, 중간에 끊어도 이미 처리한 페이지는 캐시에 남아 다음 실행에서 바로 재사용됩니다. 캐시에는 페이지 텍스트의 해시와 라벨만 저장되며 원문은 저장되지 않습니다 (설치 폴더의 `data\cache.sqlite`, `--no-cache`로 끔).

### 결과 Excel의 시트

| 시트 | 내용 |
|---|---|
| 검토 목록 | **1차·2차를 모두 통과**하고 점수 기준을 넘은 추출 등급(기본 A·B) 문장을 페이지 순서로. 번호, 섹션, 페이지, 줄, 등급, 발췌(원문 그대로), 논의 포인트, 점수, 가중치, **1차 분류기, 2차 LLM**, 판정, 비고, **피드백**, 메모 |
| 보류 | 점수 미달 A~D(사유 기재), 1차 단계의 `X?`(모델은 X 지만 기술 단서어 있음), 판정 실패 `?`. 같은 열 + 보류 사유. 피드백 열 있음 |
| 2차 제외 | **1차에서 A·B 로 뽑혔지만 2차 LLM 이 C·D·X 로 본 문장.** 잘못 제외됐는지 확인하는 시트. 피드백 열에 A/B 를 적으면 골드로 살아남 |
| 페이지 | 페이지마다 제목, 관련성(높음/낮음), 가중치, 근거, 상태(판정/제외 사유), 문장 수, 목록·보류·1차 제외·2차 제외 수, 제목 출처(placeholder/font/first-line) |
| 변경 사항 | 같은 파일의 직전 실행과 비교: 달라진 설정, 목록 진입·이탈, 등급 변경, 점수 변경, 문장 변경. 첫 실행이면 안내만 |
| 제외 페이지 | 표지, 목차, 일정, 비용, 조직, 감사, 가중치 0 등 규칙으로 건너뛴 페이지와 사유 |
| 이미지 페이지 | 텍스트가 없는 페이지. 도면이면 직접 확인 |
| 1차 제외 (참고) | 분류기가 1차에서 C·D·X 로 본 문장. LLM 은 보지 않았음. 놓친 것이 있으면 피드백 열에 A/B |
| 실행 정보 | 실행 ID, 판정 모드·흐름, **단계별 문장 수**(전체 → 1차 제외 → 2차 후보 → 2차 제외 → 보류 → 검토 목록), 모델, 분류기(학습 시각·문장 수), 페이지 가중치 켬/끔, 점수 기준, 골드 반영, 소요 시간, 직전 실행 대비, 달라진 설정, 경고 |

'판정' 열은 최종 판정 주체(분류기 / LLM / 골드)입니다. 비고 열의 `보정(A→C)`는 제목이 원인·문제·배경인 페이지에서 변경 동사가 없는 A를 C로 내린 행입니다. `분할`은 긴 줄을 문장으로 나눈 행, `표`는 표에서 나온 행, `불일치`는 1차와 2차 등급이 다른 행, `LLM 2차 제외`는 2차에서 X 로 돌려보낸 행, `골드 반영`은 골드 정답을 쓴 행입니다.

### 처리 흐름

1. **읽기**: PDF는 PyMuPDF, PPTX는 python-pptx. 제목(위쪽의 큰 글씨), 본문 줄(불릿 계층), 표를 읽습니다. 발표자 노트는 읽지 않습니다.
2. **전처리(규칙, LLM 없음)**: 제목 규칙으로 페이지 제외 → 제목으로 페이지 가중치 계산(0이면 제외) → 세 페이지 이상 반복되는 줄(머리말·바닥글) 제거 → 날짜·금액·담당자·짧은 조각 제거(보수적, 기술 단서어가 있으면 유지) → 줄 번호 부여, 80자 초과는 문장 분할.
3. **판정(cascade)**: 모든 문장을 임베딩해 분류기가 1차 등급을 냅니다. 추출 등급(A·B)으로 판정된 후보 전부를 페이지 유형별로 묶어 LLM 에 보내 2차 등급을 받습니다. LLM은 줄 수와 같은 길이의 라벨 배열만 내고 주제명이나 질문은 생성하지 않습니다. 출력이 20토큰 안팎이고 분류기가 거른 문장은 보내지 않아 CPU에서도 빠릅니다.
4. **후처리(규칙)**: 제목 기반 보정, 재현율 안전장치(`X?`), **골드 정답 반영**(골드에 있는 문장은 정답으로 덮어씀), 섹션 묶기, 논의 포인트 템플릿, **점수 계산과 보류 판정**.
5. **이력**: 설정 지문과 문장별 (해시, 등급, 점수, 목록 여부)를 설치 폴더의 `data\history` 에 저장하고 같은 파일의 직전 실행과 비교합니다. 원문과 제목은 저장하지 않습니다.
6. **출력**: Excel.

### 설정 파일 `ip_finder.toml` (선택)

설치 폴더(또는 실행하는 현재 폴더)에 두면 자동으로 읽습니다. `--config 경로`로 지정할 수도 있고, UI '페이지 가중치 → 설정 저장'이 만들어 줍니다. 설정의 상대 경로(`data/...`)는 설정 파일이 있는 폴더 기준입니다. 전체 항목과 설명은 [ip_finder.example.toml](ip_finder.example.toml) 에 있습니다. 회사 템플릿용 설정은 저장소에 올리지 않습니다 (`.gitignore` 가 `ip_finder.toml` 을 제외).

```toml
model = "qwen3:4b-instruct"          # 정확도 우선이면 "qwen3:8b"
host = "http://127.0.0.1:11434"      # 로컬 주소만 허용. 외부 주소는 실행이 거부됩니다
mode = "cascade"                     # cascade | fast | llm
target_grades = "A,B"                # 추출 대상 등급 (A,B,C,D 로 넓힐 수 있음)
embed_model = "bge-m3"               # 또는 "kure-v1"
accept_score = 0.5                   # 신뢰도 × 가중치 가 이 값 이상이어야 검토 목록
page_weight_enabled = true           # 페이지 가중치 on/off
low_relevance_weight = 0.4           # 관련성 낮음 페이지의 가중치 (0 = 판정 안 함)
low_relevance_patterns = ["(고객|클레임|영업|매출)", "(현황|실적|경과)", "KPI"]   # 제목 정규식 → 낮음
high_relevance_patterns = ["KPI\\s*개선"]                                     # 낮음보다 우선해 높음
stoplist = ["대외비", "Confidential", "○○전자 품질혁신팀"]   # 회사 템플릿의 고정 문구
page_exclude_patterns = ["목\\s*차", "일정", "비용", "예산", "조직", "감사합니다", "Q\\s*&\\s*A", "참고\\s*문헌", "부록"]
cache_path = "data/cache.sqlite"        # 캐시·분류기·이력은 설치 폴더의 data/ 아래 (설치본마다 따로)
classifier_path = "data/classifier.npz"
history_path = "data/history"           # 실행 이력. "" 이면 저장 안 함
gold_paths = ["data/gold"]              # 골드 파일·폴더. 골드에 있는 문장은 정답을 그대로 씀 (use_gold = false 로 끔)
```

## 정확도 관리: 피드백 → 골드 세트 → 학습 → 변경 확인

프롬프트, 규칙, 모델을 바꿀 때 좋아졌는지 숫자로 확인하려면 정답 세트가 필요합니다. 가장 쉬운 방법은 **결과 Excel에 바로 피드백을 적는 것**입니다.

```bash
ip-finder extract 실제보고서.pptx                 # ① 결과 Excel. 검토 목록·보류·제외 문장 시트의 '피드백' 열에
                                                #    O(맞음) / X(틀림, 제외) / A~D(올바른 등급) 를 적고 저장 (드롭다운 있음)
ip-finder feedback 실제보고서_검토후보.xlsx        # ② 피드백 → data\gold\실제보고서_gold.xlsx (있으면 합침). --confirm-unmarked: 목록의 빈 행도 맞음으로
ip-finder extract 실제보고서.pptx                 # ③ 다시 추출 → 골드 문장은 정답 그대로('골드' 판정), '변경 사항' 시트에 달라진 행
ip-finder train data\gold\*.xlsx                 # ④ 골드가 2건 이상 쌓이면 분류기 학습 (1차 판정이 회사 문체를 반영)
ip-finder history                               # ⑤ 실행·피드백·학습 이력
```

UI 에서는 정확도 관리 탭의 ②·④ 버튼과 변경 추적 탭이 같은 일을 합니다. 골드 시트를 따로 만들어 처음부터 라벨링하는 방법도 그대로 있습니다.

### 골드 정답 반영

골드 폴더(기본 `data\gold`, 설정 `gold_paths`)의 `*_gold.xlsx` 에 있는 문장이 새 실행에 다시 나오면, 모델이 판정하지 않고 **골드의 정답을 그대로** 씁니다. 결과의 판정 열은 '골드', 비고는 `골드 반영` 또는 `골드 반영(C→X)`(모델 판정과 달랐을 때)이고, 점수는 페이지 가중치와 무관하게 1.0 이라 보류로 가지 않습니다. 이 문장들은 LLM 에 보내지 않으므로 같은 보고서를 다시 돌릴수록 빨라집니다.

- 비교는 공백만 정리한 문장 전체가 같을 때입니다. 전처리가 바뀌어 문장이 달라지면 골드가 맞지 않고, 그 문장은 모델이 다시 판정합니다 ('변경 사항' 시트의 '문장 변경').
- 여러 골드에 같은 문장이 다른 정답으로 있으면 가장 최근에 고친 파일을 따르고 실행 정보에 경고를 남깁니다.
- 채점(`eval`)과 골드 시트 초안(`gold-sheet`)에는 반영하지 않습니다. 반영하면 채점이 항상 100% 가 되기 때문입니다. 모델 판정만 보려면 `--no-gold`.
- 골드 변화는 실행 이력의 '달라진 설정'에 "골드(반영 문장): 2개 파일, 180문장 → 3개 파일, 240문장" 처럼 찍힙니다.
- 골드 파일에는 실제 문장이 들어 있습니다. `data\` 는 저장소에 올라가지 않지만, 설치 폴더를 다른 곳에 복사할 때 함께 따라간다는 점은 알고 있어야 합니다.

```bash
ip-finder gold-sheet 실제보고서.pptx            # 실제보고서_gold.xlsx 생성 (모델 초안 라벨 포함)
# '라벨링' 시트의 '정답' 열에서 틀린 등급만 고친다 (A/B/C/D/X)
ip-finder eval 실제보고서_gold.xlsx            # 현재 모델·프롬프트·가중치로 다시 판정해 채점
ip-finder eval 실제보고서_gold.xlsx --stored   # 시트에 저장된 라벨을 채점 (LLM 불필요)
```

`eval` 은 등급 정확도(정밀도·재현율·F1, 혼동 행렬)에 더해 **검토 목록 정밀도**를 냅니다. 목록에 든 문장 중 정답이 추출 등급(A·B)인 비율, 등급까지 맞은 비율, 정답이 A·B 인 문장 중 목록에 든 비율(재현율)을 점수 기준 0.3~0.8 별로 표로 보여 주므로, 정밀도가 95% 를 넘는 가장 낮은 기준을 `accept_score` 로 고르면 됩니다.

### 변경 추적이 보여 주는 것

같은 보고서를 다시 돌릴 때마다 직전 실행과 비교합니다 (파일 내용 해시가 같은 실행, 없으면 같은 이름).
- **달라진 설정**: LLM 모델, 분류기(학습 시각·문장 수·골드 수), 골드(파일 수·문장 수), 프롬프트 버전, 점수 기준, 가중치 규칙, 임계값 등 결과에 영향을 주는 항목만.
- **달라진 행**: 목록 진입, 목록 이탈(보류 사유 포함), 등급 변경, 점수 변경(0.1 이상), 문장 변경(전처리가 달라짐), 새 문장, 사라진 문장.
- 이력은 설치 폴더의 `data\history\runs\*.json` 에 설정 지문과 문장별 (해시, 등급, 점수, 목록 여부)만 저장합니다. 원문·제목은 없습니다. 피드백(`feedback.jsonl`)과 학습(`train.jsonl`) 이력도 같은 폴더에 쌓여 "어떤 피드백 → 어떤 학습 → 어떤 변화"를 따라갈 수 있습니다.

```bash
ip-finder train 보고서1_gold.xlsx 보고서2_gold.xlsx   # 분류기 학습 → 설치 폴더의 data/classifier.npz
ip-finder eval 보고서1_gold.xlsx --mode cascade     # 학습 분류기 1차 + LLM 2차 채점
ip-finder eval 보고서1_gold.xlsx --mode fast        # 분류기만 채점
```

정확도, 등급별 정밀도·재현율·F1, 혼동 행렬이 출력됩니다. 학습은 임베딩에 단서어 특성 13개를 붙여 소프트맥스 회귀를 돌리며, 5겹 교차검증 정확도를 함께 보여 줍니다. 실제 보고서 2~3건에서 100~200문장이면 시작할 수 있고, 300문장을 넘기면 안정적입니다. 학습된 분류기 파일에는 문장이 들어 있지 않지만 회사 데이터로 만든 것이므로 저장소 밖에 둡니다(`.gitignore`가 `*.npz`를 제외).
**골드 파일에는 실제 문장이 들어 있으므로 저장소 바깥에 두세요.** (`.gitignore`가 `gold/`와 `*_gold.xlsx`를 제외합니다.)

### 실제 자료로 최적화하기

최적화의 중심은 골드 세트입니다. 사람이 등급을 매긴 문장이 있어야 "바꿨더니 좋아졌는지"를 숫자로 알 수 있고, `train`도 그 문장으로 합니다. 어떤 변경이든 같은 골드 파일로 전후를 재는 것이 원칙입니다.

**한 바퀴**

```bash
ip-finder gold-sheet 보고서A.pptx                   # ① 보고서A_gold.xlsx 생성. '정답' 열에 모델 초안이 미리 채워짐
#   엑셀을 열어 '정답' 열에서 틀린 것만 A/B/C/D/X 로 고친다. 다른 열은 손대지 않는다
ip-finder eval 보고서A_gold.xlsx --mode cascade      # ② 현재 상태 채점 (기준선). --mode llm 도 함께 재 두면 비교가 쉬움
ip-finder train 보고서A_gold.xlsx 보고서B_gold.xlsx  # ③ 분류기 학습 → 설치 폴더의 data/classifier.npz
ip-finder eval 보고서A_gold.xlsx --mode cascade      # ④ 학습 후 다시 채점
ip-finder eval 보고서A_gold.xlsx --mode cascade --accept-score 0.6   # ⑤ 점수 기준을 바꿔 가며 정밀도·재현율 균형점 찾기
```

- 한 보고서에서 50~100문장이 나오므로 두세 건이면 시작할 수 있고, 300문장을 넘기면 학습 결과가 안정됩니다.
- 가장 값진 문장은 결과 Excel의 '2차 제외' 시트와 비고에 "불일치"가 적힌 행입니다. 1차와 2차가 엇갈린 곳이라 그것부터 정답을 달면 같은 수고로 더 많이 좋아집니다.
- 보고서를 추가로 라벨링할 때마다 `train`에 골드 파일을 모두 넣어 다시 학습합니다. 결과 파일은 덮어씁니다.

**train이 하는 일과 바꾸는 것**

골드 문장을 임베딩한 벡터에 단서어 특성 13개(변경 동사, 단위, 숫자, 효과어, 문제어, 예정어, 비기술어, 길이, 페이지 유형)를 이어 붙여 정답 등급을 맞히는 소프트맥스 회귀를 학습합니다. 5겹 교차검증 정확도를 먼저 보여 준 뒤 전체로 학습해 저장합니다. "교차검증 정확도"가 실제 기대값에 가깝고, "학습 데이터 정확도"와의 차이가 크면 데이터가 부족하다는 뜻입니다.

| 항목 | train 전 | train 후 |
|---|---|---|
| 분류기 | 원형 문장과의 유사도(제로샷) | 학습된 회귀 모델. `check`에 "학습된 분류기"로 표시 |
| cascade 1차에서 제외되는 문장 | 원형 X 문장과 가장 비슷한 문장 | 회사 보고서에서 X 로 라벨링된 문장과 비슷한 문장 |
| fast 모드 정확도 | 원형 문장 품질에 좌우 | 회사 문체와 용어를 반영 |

train은 분류기(1차)만 바꿉니다. LLM(2차), 프롬프트, 페이지·줄 규칙, 제목 보정, 안전장치는 그대로이므로 2차에서 틀리는 문장은 아래의 다른 수단으로 고칩니다. 학습 데이터가 적을 때 1차가 기술 문장을 X 로 잘못 거르면 '1차 제외 (참고)' 시트에서 보이므로, 그 문장을 피드백해 골드에 넣고 다시 학습하세요.

**그 밖의 수단**

| 수단 | 무엇에 효과 | 하는 법 | 확인 |
|---|---|---|---|
| 2차를 8B에 맡기기 | 2차 정확도 | `--model qwen3:8b` | 1차가 거른 문장은 보내지 않아 8B 의 시간 부담이 작음 |
| 프롬프트 반례 추가 | LLM이 반복해서 틀리는 유형 | `ip_finder/label/prompts/system.md`의 예 목록에 회사 문장 유형을 다른 분야 표현으로 추가. 긴 판은 `--prompt full` | `eval --mode llm` |
| 페이지 유형 패턴 | 힌트와 제목 보정이 회사 템플릿 제목에 걸리게 | `ip_finder/prep/page_type.py`의 정규식에 "현상 분석", "Root Cause", "Action Plan" 같은 제목어 추가 | 결과 Excel의 보정 행, eval |
| 단서어 사전 | 안전장치와 분류기 특성 | `ip_finder/cues.py`의 TECH_WORDS, CHANGE_VERBS, PLAN_RE, NONTECH_RE에 회사 용어 추가 | 보류 시트와 누락이 줄어드는지 |
| 페이지·줄 규칙 | 속도와 잡음 | 설정 파일 `page_exclude_patterns`, `stoplist`에 템플릿 고정 문구 | 제외 페이지 시트, 실행 정보의 제거 줄 수 |
| 원형 문장 보강 | train 전 제로샷 품질 | 회사 PC의 `ip_finder/classify/prototypes.json`에 등급별 실제 문장 예 추가 (저장소에는 올리지 않음) | `eval --mode fast` |
| 임베딩 모델 교체 | 속도 | `--embed-model`로 더 작은 모델. 분류기는 임베딩 모델별로 다시 train | 실행 정보의 임베딩 시간 |

| 페이지 가중치 | 특정 제목의 페이지에서 올라오는 잡음 | UI '페이지 가중치' 탭 또는 `low_relevance_patterns` 에 제목어 추가. 아예 안 볼 페이지는 낮음 가중치 0 | '페이지' 시트, `ip-finder pages`, eval 의 목록 정밀도 |
| 점수 기준 | 목록 길이와 정밀도의 균형 | `accept_score`, UI '목록 점수 기준' | eval 의 점수 기준별 표 |

**혼동 행렬로 고르는 처방** (행 = 정답, 열 = 예측에서 큰 칸을 본다)

| 정답 → 예측 | 뜻 | 처방 |
|---|---|---|
| C → A | 원인·현상 설명을 수단으로 봄 | 페이지 유형 패턴에 회사 제목어 추가, system.md 반례, 골드 추가 후 train |
| A → B | 수단과 수치가 함께 있는 문장을 효과로만 봄 | system.md에 "…으로 변경하여 30% 저감 → A" 같은 예 추가, train |
| A → D | "적용"이 들어가면 계획으로 봄 | PLAN_RE를 "예정·검토 중"으로 좁히기, train |
| X → A~D | 잡음이 목록에 들어옴 | 그 문장들의 페이지 제목을 보고 낮음 키워드 추가, 점수 기준 상향, NONTECH_RE와 HARD_EXCLUDE, 페이지 제외 패턴, stoplist 보강 |
| A~D → X | 기술 문장이 빠짐 | '2차 제외'·'1차 제외 (참고)' 시트에서 피드백해 골드에 넣고 train, TECH_WORDS에 회사 기술 용어 추가(안전장치가 살림). 정밀도 우선이므로 소수의 누락은 감수 |

순서는 규칙과 패턴을 먼저 손보고, 그다음 train, 마지막에 프롬프트를 만지는 편이 좋습니다. 규칙은 결정적이라 되돌리기 쉽고, train은 데이터만 쌓이면 자동으로 좋아지며, 프롬프트는 한 곳을 고치면 다른 곳이 흔들릴 수 있어 반드시 eval로 전후를 비교해야 합니다.

## 보안

- 모든 LLM 호출은 `127.0.0.1`의 Ollama로만 갑니다. 설정에 외부 주소를 넣으면 실행 자체가 거부됩니다 (`tests/test_llm.py`).
- 외부 서비스 SDK, 텔레메트리, 자동 업데이트가 없습니다. 의존성은 PyMuPDF, python-pptx, openpyxl, numpy 뿐입니다.
- 캐시, 실행 이력, 로그에 원문을 남기지 않습니다. 원문이 들어가는 파일은 결과 Excel 과 골드 시트뿐이며 원본 옆에 생깁니다. 프로그램의 상태 파일은 설치 폴더 밖(사용자 홈 등)에 만들지 않습니다.
- 실제 보고서와 골드 세트는 저장소 바깥 폴더에 두고, 코드 작성에 AI 도구를 쓸 때 그 폴더를 열지 마세요.
- 오프라인 확인: 윈도우 방화벽에서 `python.exe`와 `ollama.exe`의 아웃바운드를 차단해도 정상 동작해야 합니다. 윈도우 방화벽은 루프백(127.0.0.1)을 막지 않으므로 Ollama 연결은 유지됩니다.

  ```bat
  netsh advfirewall firewall add rule name="ip-finder python block" dir=out program="C:\경로\.venv\Scripts\python.exe" action=block
  netsh advfirewall firewall add rule name="ollama block" dir=out program="C:\Users\<이름>\AppData\Local\Programs\Ollama\ollama.exe" action=block
  ```

## 성능 참고

같은 12장 샘플(판정 대상 7페이지, 27문장, 정답이 A·B 인 문장 15개)을 GPU 가속이 되는 Apple M4에서 v0.5.1 로 돌린 결과입니다. 정답은 설명용 샘플에 직접 매긴 것이고, 원형 문장도 이 샘플을 알고 쓴 것이라 실제 보고서에서는 골드 세트로 다시 재야 합니다. "목록 정밀도"는 검토 목록에 든 문장 중 정답이 A·B 인 비율, 재현율은 정답 A·B 문장 중 목록에 든 비율입니다.

| 모드 (추출 등급 A·B) | LLM | LLM 호출 | 시간 | 단계별 문장 | 목록 | 목록 정밀도 | 등급 일치 | 재현율 |
|---|---|---|---|---|---|---|---|---|
| cascade (기본) | 4B | 4 | 6초 | 27 → 1차 제외 13 → 2차 후보 13 → 2차 제외 1 | 12 | 100% | 100% | 80% |
| cascade | 8B | 4 | 9초 | 같음 | 12 | 100% | 100% | 80% |
| fast (분류기만, 제로샷) | - | 0 | 1.5초 | 27 → 제외 13 | 13 | 100% | 92% | 87% |
| llm (전부 LLM) | 8B | 7 | 12초 | 27 → 2차 제외 13 | 14 | 100% | 100% | 93% |
| cascade, 추출 등급 A·B·C·D | 4B | 4 | 7초 | 27 → 1차 제외 2 → 2차 후보 24 | 24 | (C·D 포함) | 96% | - |

- 추출 등급을 A·B 로 좁히면 2차 후보가 24 → 13 문장으로 줄어 LLM 시간이 그만큼 줍니다 (4B 기준 7초 → 6초의 LLM 몫, 묶음 수는 같아 호출 수는 4회 그대로. 문장이 많은 실제 보고서에서는 묶음 수도 줄어듭니다).
- cascade 의 목록 12문장은 전부 정답 A·B 였고 등급도 다 맞았습니다. 놓친 3문장은 분류기가 1차에서 C·D 로 본 것(예: "도포량 자동 제어로 두께 편차 관리")으로 '1차 제외 (참고)' 시트에 있습니다. 골드로 학습하면 1차가 회사 문체를 배워 이런 누락이 줄어듭니다.
- 4B 와 8B 의 결과가 같았습니다. 2차에 보내는 문장이 적어 8B 를 써도 3초 차이뿐이니, 회사 골드로 재서 정밀도가 같으면 4B 를 쓰면 됩니다.
- 이 샘플에는 관련성 낮음 제목이 없어 가중치 효과는 나타나지 않습니다. 현황·고객 대응 페이지가 있는 실제 보고서에서 차이가 납니다.

CPU 전용 PC에서는 5~8배 느릴 것으로 추정합니다. 80장 보고서(규칙 제외 후 50장, 400문장 안팎, A·B 후보 150문장 안팎)면 임베딩 2~3분에 LLM 2차가 4B 로 2~3분, 8B 는 그 두 배인 그림입니다. 1차에서 걸러진 문장, 골드 문장, 관련성 낮음 가중치 0 페이지는 LLM 에 가지 않습니다. `ip-finder extract --mode fast` 로 먼저 돌려 보면 그 PC 의 임베딩 속도를 바로 알 수 있습니다.
